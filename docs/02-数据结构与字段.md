# 02 · 数据结构与字段

本系统的主数据是一个**结构化的多维表格**（表 / 记录 / 字段，有固定 schema），不是非结构化文档。它属于 Airtable 一类的「富类型表格库」：字段类型丰富，用视图/界面而非 SQL 来检索，schema 可随时调整。

## 一、字段表

一条记录包含以下字段（可按个人需求裁剪）：

| 字段 | 类型 | 说明 |
|---|---|---|
| 事项 | 文本（主字段） | 这件事是什么，一句话 |
| 领域 | 单选 | 工作 / 家 / 兴趣 / 健康 / 其他——只作筛选标签，不分桶 |
| 时长 | 单选 | 5分钟 / 半小时 / 2小时+ |
| 精力 | 单选 | 低 / 中 / 高 |
| 场景 | 多选 | 手机 / 电脑前 / 在家 / 外出 / 任何 |
| 价值 | 单选 | 高 / 中 / 低 |
| 状态 | 单选 | active / someday / done / 触发 / 放弃（见下） |
| 入池日期 | 日期 | 录入当天，默认创建时间 |
| 备注 | 文本 | **静态**：这件事是什么、为什么做、要注意什么 |
| 孩子 | 单选 | 我先做 / 孩子A / 孩子B / 俩孩子一起（如有孩子场景） |
| 地点 | 多选 | 超市 / 药店 / 商场 / 邮局 / 书店 / 菜市场 / 加油站 |
| 完成日期 | 日期 | 标 done 时自动填当天 |
| 跟进记录 | 文本 | **动态**：进行到哪了的流水账，只增不改 |
| 兴奋点 | 多选 | 懂原理 / 要成品 / 省事 / 连接人 / 好看好玩 |
| 条目类型 | 单选 | 想做事项 / 提醒指针（见 04 工作库衔接） |
| 工作编号 | 文本 | 关联外部工作任务的编号（如有） |

> 字段命名可按你的实际场景调整；关键是区分清楚「静态背景」与「动态流水」。

### 两个易混字段的分工

- **备注** = 这件事是什么（静态背景）。
- **跟进记录** = 这件事进行到哪了（动态流水）。

跟进记录写法：一行一次、带日期、只记动作和结果不记心情；结尾留【当前状态】+【待决策】两个块。回答前先读跟进记录，再说话。

## 二、五个状态

| 状态 | 含义 |
|---|---|
| `active` | 现在能做 |
| `someday` | 现在做不了，或还没想清楚从哪下手 |
| `done` | 做完了（保留在池子里，是成就的证据） |
| `触发` | 只在特定情境被调取（如采购清单），**永不参与「闲了」** |
| `放弃` | 想过，但不做 |

**`放弃` 是正经状态，不是垃圾篓。** 它精确记录「这件事我想过，但我不做」，和 `done` 一样是可用的事实。混在一起，将来就分不清「做成了多少」和「想过多少、放弃了多少」这两种完全不同的情况。

## 三、视图设计

同一张表配多个视图，各自持久化筛选/排序/分组，共享同一份数据：

| 视图 | 类型 | 用途 |
|---|---|---|
| 表格 | 网格（grid） | 全量浏览与编辑 |
| 状态看板 | 看板（kanban） | 按「状态」分列，一眼看各状态分布 |
| 入池日历 | 日历（calendar） | 按「入池日期」查看录入节奏 |
| 闲了候选 | 网格（grid） | 筛选：状态 ∈ active/someday 且 条目类型 = 想做事项 |

「闲了候选」视图是查询的基础集合：`done`、`触发`、`放弃` 以及外部工作的「提醒指针」都不进入推荐池。

## 四、为什么用富类型表格而不是纯文本清单

- 单选/多选字段可点选、可分组、可配色，不用手打自由文本，检索口径稳定。
- 日期字段支持排序与相对时间筛选，配合日历视图。
- 多视图让同一份数据有多个入口：看板看状态、日历看节奏、筛选视图看「闲了候选」。
- schema 可随时演进，新增字段不影响历史记录。
